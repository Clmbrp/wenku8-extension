# Wenku8 来源架构决策

日期：2026-11-22。证据含义与 [访问审计](ACCESS_AUDIT.md) 一致：**[实测]** 为 Codex 观察，**[浏览器证据]** 为用户在已登录 Fedora Chrome 中的实测，**[源码]** 为参考代码，**[不确定]** 为尚待验证。本文是设计边界，不表示相关功能已实现。

**[样本]** 用户提供了保存的页面 HTML 和搜索行为说明；其中的文件内容与网络响应实测应分别看待。下列结构与决策的详细依据见访问审计。

## 方案选择

**[阶段 2 真机通过，用户提供]** 用户在 Mihon WebView 手动完成站点验证后重新从 HTTPS 入口登录，随后普通客户端成功加载真实热门书目。`WenkuSession` 只检查当前请求 URL 下宿主 Cookie 的登录标识，用于解释登录跳转。`WenkuAccess` 依据 HTTP 状态、响应标记和文档区分登录、安全验证与直接拒绝，榜单解析成功才确认该次数据访问可用。来源设置通过 `getHomeUrl()` 在下次打开 WebView 时选用 HTTPS 登录页或 HTTPS 榜单，继续由宿主管理 Cookie。

**[阶段 2 限制]** 复用宿主客户端的 CookieJar，手动按最多 5 次同源 HTTPS 跳转获取页面，单请求 30 秒超时、禁止自动连接重试及缓存命中；禁止对 429 自动切换 WebView 或重试。插件移除已识别的 Mihon `CloudflareInterceptor` 和 OkHttp 日志拦截器，避免宿主自动启动后台验证及常见头部日志；这不保证其他宿主或系统日志的行为。交互式登录使用宿主来源页面的 WebView 入口，不在插件中复制浏览器或存储密码。其他版本宿主能力、Cookie 共享、普通 HTTP 可行性未验证；遇 403 或验证页面仅提示，由用户决定是否打开 WebView，不能假设会话能够解决拦截。

**[实测]** Codex 所用代理下首页曾返回 Cloudflare 403，用户设备在上述会话下成功访问。**[源码]** LightNovelReader 和 LiteTale 分别展示浏览器内核与普通 HTTP 解析 HTML 的不同实现。**[不确定]** 其他设备和网络的行为尚无证据。

**主方案 A。** 以 Mihon `HttpSource` 的 `client` 按需获取网页 HTML，并以实际响应和可解析的内容判断访问结果。

**方案 B。** 由用户主动打开 Mihon 提供的 WebView，手动处理站点显示的验证或从 HTTPS 入口登录。遇到 403 或验证页时停止当次插件请求，由用户决定是否打开 WebView。

**[不确定] 备选 C：** 仅对有可核验授权、文档和使用限制的正式数据通道开放适配。MewX 自建中继与站点网页、站点正式 API 是不同系统；本项目不使用其私有接口、中继、密钥或协议。

## 搜索结果判定与章节内容模型

**[浏览器证据]** 已登录 Chrome 搜索「化物语」时经过 `POST /so.php` → 302 → `GET /modules/article/search.php?...` → 302 → `GET /book/6.htm` → 200；搜索「化」返回多结果。**[不确定]** 唯一匹配是否为跳转条件、其他搜索及 Mihon 网络行为仍待验证。设计上安全处理重定向及其最终 URL，以页面类型与必要字段综合判定：结果页映射为多本书，详情页映射为单本书，明确的无结果页才返回空结果；未知结构、拦截或登录页面返回对应错误。无需把此例假定为 JavaScript 跳转，也不能执行任意脚本或绕过验证。

**[样本]** 内部章节内容拟表示为按 DOM 原始顺序排列的 `List<ContentBlock>`：`Text(text)` 和 `Image(resolvedUrl)`。遍历 `#content` 时保留文本与换行位置，识别 `img` 并解析地址，排除样本中的 `ul#contentdp` 导航，避免同时把图片链接和其中图片作为两个块。相邻文字可以合并，但不能跨图片合并；空白清理不能改变阅读顺序。纯文字只有文本块，纯插图只有图片块，图文混排按原有顺序交错。

**[浏览器证据]** 已登录 Chrome 在禁用缓存后成功通过 HTTPS 获取一张 `pic.777743.xyz` 的 JPEG；不能由此推断全部图片、其他小说或 Mihon OkHttp 可访问。**[不确定]** 混排模型目前仅有[虚构样本](fixtures/wenku8/chapter_mixed_synthetic.html)，不是实际混排页面的验证；文本分页、章节合并、图片失败与 Mihon `Page`/渲染映射需真机证明。相对 URL 使用实际响应的最终页面 URL 及经验证的 `<base>` 语义解析，跨域图片不得自动携带站点敏感会话；图片授权、Referer/明文 HTTP 策略均待验证。

## 数据流与失败处理

**[阶段 3 第一批]** 用户打开榜单或单部书籍时，来源按需获取同源 HTTPS 页面，再检查响应、解码、解析并映射到 Mihon 数据模型。列表从书籍 ID 得到经过样本验证的 HTTPS 封面地址，详情按需解析元数据。目录使用详情页实际给出的同书路径，章节按目录识别卷次和插图条目，再按 Mihon 的新章在前顺序交付。

**[阶段 3 第二批]** `WenkuBrowse` 根据 Mihon 给出的页码请求热门榜、更新榜或搜索结果。首屏搜索用 GBK 表单，后续优先请求同一关键词已解析的完整分页链接。页内按书籍路径合并，跨页去重交由 Mihon。遇到不符的页码、列表结构或登录和验证响应时保留对应错误。

**[阶段 3 稳定性]** `WenkuPages` 复用宿主会话和同源 HTTPS 跳转规则，`WenkuRequestPolicy` 对主站 HTML 请求统一排队、合并相同在途请求并传递取消。1.6.9 在共享冷却期间挂起请求，收到限流响应时会等待并恢复一次。搜索结果端点有独立的起发间隔，等待期间不占用请求队列。封面 CDN 走独立链路。

**[不确定]** 用户可操作的登录或验证提示，应区分站点登录失效、站点防护拦截和普通网络失败。403 只表明请求被拒绝；429 表示限流时停止自动请求并尊重站点指示。无论状态码是否为 200，都要防止登录页或拦截页被误判为有效内容。严禁自动识别、求解或绕过人机验证。

## 阶段 4.1 文字页

- `WenkuReader` 通过 `WenkuPages` 访问 `/novel/{分组}/{书籍 ID}/{章节 ID}.htm`。沿用已有的字符编码、会话、节流和错误分类，并校验最终章节路径。
- `WenkuChapterParser` 在已知章节结构中按 DOM 顺序解析标题、文本和图片地址。4.1 的文字渲染消费其中的文本块。
- `WenkuTextRenderer` 将正文一次交给 Android `StaticLayout` 排版，再根据行的实际高度分配图片。每页从相同布局裁出互不重叠的行，标题只绘制在首图。位图上限 1,000 × 2,000，PNG 压缩后释放位图。
- `WenkuPageRef` 使用布局版本、规范章节路径、正文与标题的 SHA-256 和页码组成稳定地址。Mihon 的图片请求在 `wenku8-reader.invalid` 被本地拦截，正文不会写入 URL。
- `WenkuTextCache` 在宿主应用缓存目录中保留最多 24 份、共 16 MiB 的章节快照，新开章节可复用 20 分钟内的快照。内存最多保留 3 个章节的排版和 16 张 PNG（总计最多 8 MiB）。Mihon 仍管理自己的图片缓存。内存被逐出后可从对应快照重排。若快照也缺失，拦截器通过现有网络策略限时回取同一章节，核对版本摘要后才渲染。若站点已修改正文，旧页面地址会提示更新。HTML 请求使用独立 OkHttp 调度器。

## 阶段 4.2 插图与图文页

- 阅读页按内容块顺序生成，连续文字沿用 `StaticLayout` 和 `Canvas`，每张插图占一页。标题绘制在首个页面，流中的说明段落保留在原位置。正文只有图片时也可生成有效页列表。
- `WenkuIllustrations` 在本地图片请求触发时取一张原图，限制响应体和同时取图的数量。同站请求共享 HTML 队列和冷却，外域只以 HTTPS 访问且不携带站点 Cookie。先读原图尺寸，再采样解码，单张解码目标上限为 4096 像素边长和 400 万像素，输出 PNG 上限为 1000 × 2000。保留整幅图的比例，压缩后释放 Bitmap。每页独立失败且没有自动重试。
- 纯文字页延续 `v1` 地址。含图章节使用 `v2` 地址，将标题、块类型、顺序、正文和图址纳入摘要。旧文字快照仍可用于恢复先前地址。升级后，如果 Mihon 持有旧的文字页列表，会先使用它，直到宿主刷新页面列表才出现新增插图。已经下载的章节继续使用原有下载文件。
- 1.6.11 文字 PNG 自身为白底，通常有上下各 52 px 留白，页面高度随内容变化。没有标题的插图上下各 12 px 留白。Mihon 条漫使用内容高度，非连续模式另加 15 dp；黑底并显示「上一章／本章」的是宿主章节过渡页。 [Mihon 页间距](https://github.com/mihonapp/mihon/blob/feadad5e1e2bf638be6e2ca317d11657b09d4596/app/src/main/java/eu/kanade/tachiyomi/ui/reader/viewer/webtoon/WebtoonPageHolder.kt) · [Mihon 章节过渡](https://github.com/mihonapp/mihon/blob/feadad5e1e2bf638be6e2ca317d11657b09d4596/app/src/main/java/eu/kanade/tachiyomi/ui/reader/viewer/webtoon/WebtoonTransitionHolder.kt)

## 阶段 4.3 阅读样式与页列表刷新

- 设置保存在每个来源的 `SharedPreferences`。`WenkuReadingStyle` 将列表选项转换为固定安全范围内的排版参数和成对的预设色。跟随模式优先读取 Mihon 的应用主题，再由 AppCompat 和系统夜间配置补充。每次生成页列表时读取一次，整章使用同一份样式快照。
- `StaticLayout` 用调整后的字号、宽度和行距排版。段距只调整正文相邻换行形成的空行高度，保留正文字符和单独的换行。纯文字和混排仍按真实行边界逐页截取。非标题页上下 20 px，标题上方 52 px，短页继续随实际内容确定高度。插图的渲染背景随样式调整，保留原始颜色和固定的左右补边。 [Android LineHeightSpan](https://developer.android.com/reference/android/text/style/LineHeightSpan)
- `v3` 页面 URL 包含渲染版本、已解析样式、章节路径、正文摘要和页码。排版和 PNG 缓存分别以该组合索引。磁盘章节快照继续使用与样式无关的 `v1` 和 `v2`。升级前的页面 URL 保留对应的旧排版，因此旧页仍可正确恢复。旧样式文件由 Mihon 原有缓存淘汰规则回收。
- Mihon 在打开阅读器时先用宿主保存的页列表，来源 API 无法替换已经打开的列表。插件的「应用到已读章节」只在用户点击后扫描 Mihon 已知格式的 `chapter_disk_cache`，只失效能校验为同一 Wenku8 章节、同一摘要和旧样式的页列表文件。图片、其他来源、缓存索引和阅读进度留在原处；无法识别的缓存布局会跳过。宿主把页列表缺失视为缓存未命中，重开时再次调用来源，随后由插件按已有正文快照重新计算页数。仍保留磁盘快照的已读章节可在刷新后复用一次超过正常时效的正文。 [DiskLruCache 缓存未命中实现](https://github.com/JakeWharton/DiskLruCache/blob/master/src/main/java/com/jakewharton/disklrucache/DiskLruCache.java)
- Mihon 的进度单位是页码。更改字号等参数后，旧页码对应的正文位置可能改变。

## 阶段 5.1 Mihon 下载与离线读取

- Mihon 0.21.3 的下载队列从来源 `getPageList()` 取得章节页，按列表顺序重新编号。Wenku8 把同一个本地渲染地址同时填入 `Page.url` 和 `Page.imageUrl`。下载正文及插图走与在线阅读相同的 PNG 响应。原图会按已验证的阅读尺寸等比缩放并嵌入 PNG。图片宽高、并发解码数和内存缓存仍有限制。
- Mihon 复用已有在线图片缓存或下载进度中的完整文件。部分下载重试时，完整的 HTTP 200 PNG 会覆盖 `.tmp`，只有 HTTP 206 才会追加。全部页面完成并通过数量检查后，Mihon 才生成 CBZ（启用时）或完成目录。后台失败仍交由 Mihon 标记、重试和继续任务。下载进行中宜保持同一阅读样式，宿主在重启后可按页码复用已暂存的图片。
- 已完成的章节由 Mihon 的本地归档或目录加载器读取。它按文件名自然排序，翻页从本地流读图。下载产物冻结当时的字号、间距和配色，更新在线样式继续通过原来的页列表刷新，仅在用户选择重新下载时才会得到新版样式的离线文件。 [下载源码](https://github.com/mihonapp/mihon/blob/v0.21.3/app/src/main/java/eu/kanade/tachiyomi/data/download/Downloader.kt) · [离线加载源码](https://github.com/mihonapp/mihon/blob/v0.21.3/app/src/main/java/eu/kanade/tachiyomi/ui/reader/loader/DownloadPageLoader.kt)
- 外部插图使用与主站分离的节流和冷却，429 优先采用 `Retry-After`，缺省 30 秒。Mihon 发来的重试必须在冷却期后才能访问图床，取消后的等待或图片请求可以退出。主站章节 HTML 仍按原队列执行，并可命中与样式无关的正文快照。若任务仍持有旧页地址，缓存恢复会按其中的样式和正文摘要排版，源内容已经变化则报错。

## 阶段 5.2 阅读缓存与取消

- 原始 HTML 仅在请求时解码和解析。章节路径相同的冷加载合并，解析后的章节快照与样式无关。磁盘保留 24 份、总计 16 MiB，单份最多 4 MiB。普通打开沿用 20 分钟时效。旧阅读页仍可按精确摘要读取历史快照。最近解析结果在内存中保留最多 6 份、估算文本和链接载荷最多 1 MiB，命中时核对磁盘文件的大小和修改时间。
- 正文排版以章节摘要和样式为键，PNG 另外按页码区分。排版缓存通常最多 2 个、估算载荷 1 MiB，超限长章节可以独占一个位置，避免每翻一页都重排。该载荷是淘汰权重。PNG 缓存最多 8 张、4 MiB，超过单项容量的 PNG 直接交付。仅在读取该页时生成图像，文字绘制和插图绘制共用一个可取消的排队锁。
- 同一合成页的请求合并。取消最后一个请求者会停止尚在等待或正在取图的任务。Android 当前执行的一次布局或压缩完成后检查取消，丢弃已取消的结果。插图最多同时暂存一份网络响应数组，单张压缩数据上限 12 MiB，解码上限保持原值，Bitmap 用完立即释放。插件复用既有 HTTP 客户端和 Mihon 图片缓存。
- 维护只处理插件正文目录的已知快照文件及超过 24 小时的遗留 `pending-*.tmp`。已下载 CBZ／目录、历史快照目录和 Mihon 阅读记录由其原有流程管理。

## 阶段划分和验证门槛

- **[样本 + 不确定] 可作为下一阶段离线编码输入：** URL 和字符集工具、搜索结果类型分支、合成 HTML 的解析器、字段映射、有序内容块、失败类型及 Kotlin 层接口；URL 和选择器保持可替换并注明证据等级。阶段 2 的离线原型具备启动基础，不代表联网或发布已获验证。
- **[阶段 2 真机验证]** 该设备已完成 HTTPS 登录、人工验证和普通客户端榜单访问。会话续期、网络变化和其他设备的行为仍需观察。
